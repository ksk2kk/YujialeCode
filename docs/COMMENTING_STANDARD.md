# YJLcoder 教材注释规范

这份规范约束项目内新增注释，防止后续代码又回到“只有作者自己看得懂”，也防止注释
膨胀成逐字翻译代码的噪音。

## 模块开头必须回答

每个手写源码文件顶部必须说明：

1. 它在 Agent 中的单一职责；
2. 上游输入来自哪里；
3. 下游输出交给谁；
4. 主要对象的生命周期和线程边界；
5. 至少一个通俗比喻（比喻必须解释结构，不能只卖萌）。

## 结构体字段必须回答

对跨函数、跨线程或持久化的结构体字段，注释说明：

- 字段保存的是原始值、快照、共享句柄还是缓存；
- 谁修改它，是否需要 Mutex/Atomic；
- `Option` 的 None、集合为空、数值 0 分别表示什么；
- 是否写入磁盘/发送到模型/显示给用户；
- 什么时候销毁。

## 函数注释模板

复杂函数优先使用下面的四段语义，而不是机械列 `# Arguments`：

```text
/// 做什么，以及为什么在这一层做。
///
/// 输入从哪里来；按值参数是否移动，引用参数借用多久。
/// 主要副作用与线程/取消行为。
/// Ok/Err/事件分别交给哪个调用者。
```

## 局部变量何时需要注释

必须注释：

- 状态机当前状态、跨循环累计器、熔断计数；
- channel 两端、Arc clone、Mutex guard；
- 为规避竞态/截断/Unicode 边界而存在的索引；
- 乐观 UI 状态和最终真实状态的区别；
- 变量名无法表达的单位（秒、token、字节、行号是一基还是零基）；
- `unsafe` 边界与成立条件。

不应注释：

- `let len = text.len()` 上方再写“取得长度”；
- `i += 1` 上方再写“i 加一”；
- 已由清楚的函数名和类型完整表达的临时变量。

## 注释也要接受测试

修改逻辑时同步检查附近注释。错误注释比没有注释更危险：它像地图上画了一座不存在的
桥。代码审查时，生命周期、默认值、路径、阈值和线程数量属于必须核对的“可过期事实”。
