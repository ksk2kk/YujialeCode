# Claude Code Best 参考采纳清单

> 本文件是“外部参考来源索引”，不是运行时代码。它的寿命随源码仓库长期保存，用来
> 回答某段设计借鉴自哪里；程序启动时不会读取它。YJLcoder 只借鉴工具/UI/控制层思想，
> 品牌和面向本地弱模型的短提示词体系保持独立。

参考仓库：<https://github.com/claude-code-best/claude-code>

YJLcoder 只借鉴工程机制与交互行为，保持独立 Rust 实现；系统提示词、品牌、云端绑定和 React/Bun 技术栈不引入。所有功能都以本地模型的小上下文、低并发和可恢复性为优先级。

## 已采纳

- 工具按分类动态发现，原生模式保持稳定且很小的入口集合。
- 工具循环、重复结果、连续失败由控制层熔断，不依赖提示词自律。
- 会话、Trace、技能和配置按数据目录隔离。
- 超长工具结果完整写入 `~/.yjlcoder/tool-results/<session>/`，上下文只保留路径和头尾预览。
- 自动压缩按实际上下文窗口动态计算目标预算。

## 下一阶段

1. 权限策略：把只读、写文件、执行命令和联网分级，规则由代码判断。
2. 命令注册表：将斜杠命令从主循环拆成稳定、可测试的注册与分发层。
3. Turn journal：记录每轮状态和未完成动作，进程重启后可安全恢复。
4. 后台任务：长命令异步运行，可查看状态、读取增量输出和取消。
5. Hooks：在工具执行前后提供本地脚本钩子，默认关闭且有超时。
6. Provider 适配：继续保持 OpenAI 兼容主路径，为本地端点单独处理能力探测和降级。

## 暂不采纳

- 大型常驻系统提示词和完整工具 Schema 注入。
- 依赖云账号、遥测或远程控制的功能。
- 一次性复制完整文件快照；参考项目自身已因内存增长关闭该机制，后续如做回退应采用增量 diff。
- 多 Agent 编排默认开启；本地单模型先保证单 Agent 收敛、可观测和可恢复。

## 实施原则

- 能在控制层确定的行为不写进提示词。
- 所有循环、队列、输出和重试都有硬上限。
- 完整数据可追溯，上下文只放最小必要预览。
- 新能力必须有离线测试，不能依赖真实模型才能验证。
